# PR-01 · Design foundation

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the existing CSS variables and fonts in `app/src/renderer/`
with the moodboard's design tokens, and install the motion library used by
later PRs. After this PR, the app still works exactly as before — only the
colors, type, radii, and base CSS change.

**Architecture:** All tokens live as CSS custom properties on `:root` in
`index.css`. No Tailwind, no CSS-in-JS. The motion library is `framer-motion`
(maintained, small, used directly via `<motion.div>` and `AnimatePresence`).

**Tech stack:** CSS custom properties, `framer-motion@^11`, Inter (via
`@fontsource/inter`), Instrument Serif (via `@fontsource/instrument-serif`).

## Global constraints

- TypeScript strict mode stays on (`noUncheckedIndexedAccess`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch`).
- No new runtime deps beyond what this PR lists.
- Tokens must be plain CSS variables — no Tailwind config, no `theme.ts`.
  Anyone reading `index.css` should see every token in one place.
- `pnpm.onlyBuiltDependencies` must include any new native dep; the deps
  added in this PR are not native, so no change there.

---

## Files

- Modify: `app/package.json` — add three new deps.
- Modify: `pnpm-lock.yaml` — regenerated by install.
- Modify: `app/src/renderer/index.css` — replace `:root` block and any
  hard-coded color rules. ~750 lines → ~250 lines after consolidation.
- Modify: `app/src/renderer/main.tsx` — import the new font CSS at the
  top of the module so fonts load before React mounts.
- Create: `app/src/renderer/lib/motion.ts` — re-export `framer-motion`
  primitives + duration/easing constants so components don't import the
  library directly (single chokepoint for future swap).
- Create: `app/tests/renderer/tokens.test.ts` — snapshot the resolved
  values of the spec tokens so future CSS edits can't silently change them.

### Task 01.5 — Snapshot test for tokens

This guards against silent token drift in later PRs.

- [ ] Create `app/tests/renderer/tokens.test.ts`:

  ```ts
  import { describe, expect, it } from 'vitest';
  import { readFileSync } from 'node:fs';
  import { resolve } from 'node:path';

  const CSS = readFileSync(
    resolve(__dirname, '../../src/renderer/index.css'),
    'utf8',
  );

  const expected: Record<string, string> = {
    '--plover-bg': '#0a0b0b',
    '--plover-surface': '#141516',
    '--plover-text': '#f1ecdf',
    '--plover-mint': '#b7e4c7',
    '--plover-radius-xl': '28px',
    '--plover-duration-normal': '220ms',
  };

  describe('design tokens', () => {
    for (const [name, value] of Object.entries(expected)) {
      it(`declares ${name} as ${value}`, () => {
        const pattern = new RegExp(`${name}:\\s*${value.replace(/[.*+?^${}()|[\\]\\\\]/g, '\\\\$&')};`);
        expect(CSS).toMatch(pattern);
      });
    }
  });
  ```

- [ ] Run: `pnpm --filter ./app exec vitest run tokens` — expect 6 passing.

## Risks / footguns

- **electron-vite externalization** — adding `framer-motion` may need it
  external in `app/electron.vite.config.ts` if the main process ever
  imports it (it won't — renderer-only). Confirm `pnpm build` still
  produces a working `out/`.
- **`@fontsource/*` and `pnpm.onlyBuiltDependencies`** — these are
  not native modules. No allowlist change required.
- **TCC / Downloads access does not affect this PR**, but if the agent
  attempts to read system fonts directly, it will hit the same permission
  wall noted in earlier lessons-learned. Stick to `@fontsource/*`.
